# Update to plcc-ng 2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt plcc-ng 2.0.0, pin the devcontainer image by digest, and restore the original course-material identifiers where 2.0.0 now allows — across the three migrated languages V0, V1, V2.

**Architecture:** Three phases in order. Phase 1 (Tasks 1–2) adopts 2.0.0 and makes the one *forced* change — `_run()` must return a string instead of printing — verifying the suite goes green before any cosmetic edit. Phase 2 (Tasks 3–5) restores identifiers per language: the `VAR` token becomes `SYMBOL` (field `symbol`, class `VarExp` unchanged), and V2's `IfExp` children return to camelCase. Phase 3 (Task 6) closes the three upstream-defect issues. Each language's `bats` suite is the regression gate for its own changes.

**Tech Stack:** `plcc-ng` 2.0.0 CLI (`plcc-rep`), installed as a global pipx app; `bats-core`; bash; Python 3.12, Java JDK 21, Node.js 18 — all already in the devcontainer.

## Global Constraints

- **Scope is V0, V1, V2 only.** Do not touch V3–V6 or any other language, `Env`, `Val`, or `Prim` logic. They migrate later and inherit these conventions then.
- **Devcontainer image pin (exact value):** `ghcr.io/ourplcc/devcontainers/plcc-ng:2.0.0@sha256:8e0123b52bd6bda9b60bb15d03d3b1922b9a56ce79565bd52bca195f6d3f0979`
- **`SYMBOL` convention:** the token that lexes identifiers is `SYMBOL` (was `VAR`); it is captured as bare `<SYMBOL>`, so the auto-generated field is `symbol`. Never alias it and never reintroduce `var` — `var` is a JavaScript reserved word and 2.0.0 rejects it as a specification error.
- **AST class name stays `VarExp`.** Only the token and field change. Do not rename the `VarExp` alternative or class.
- **`IfExp` children are camelCase:** `testExp` / `trueExp` / `falseExp` (2.0.0 preserves alt-name casing).
- **Nonterminals stay PascalCase** (`<Program>`, `<Exp>`, `<Prim>`, `<Rands>`) — plcc-ng requires it.
- **`_run()` returns a string; the runtime prints it.** Direct stdout printing (`print`, `System.out.println`) is not permitted in `_run()` on 2.0.0.
- **Structural fidelity across targets:** method names (`eval`, `apply`, `evalRands`, `_run`, `applyEnv`) and behavior stay identical across Python, Java, JavaScript. These changes preserve output exactly — every `*.expected` file stays untouched.
- **Course-material impact is logged in the same commit as the change** that causes it, in [dev-docs/course-material-impact.md](../course-material-impact.md), under the affected language's heading (per [CLAUDE.md](../../CLAUDE.md)).
- **Commit types:** these changes preserve user-facing output, so use `refactor`/`build`/`docs` — never `fix`/`feat` (which bump the release version via `.releaserc.yaml`).
- Full design context: [dev-docs/specs/2026-07-27-plcc-ng-2.0.0-update-design.md](../specs/2026-07-27-plcc-ng-2.0.0-update-design.md); issues [#3](../issues/003-python-run-return-value-quoted.md), [#4](../issues/004-js-var-field-reserved-word.md), [#6](../issues/006-multi-capture-alt-name-case-mismatch.md).

```markdown
- The identifier token is renamed from `VAR` to **`SYMBOL`**, and captured
  as bare `<SYMBOL>`, so `VarExp`'s field is **`symbol`** (`self.symbol` /
  `symbol` / `this.symbol`), not the original `var`. This corrects a
  misnomer — in V0–V6 a `SYMBOL` names an immutable binding, not a mutable
  variable — and sidesteps the `var`/JavaScript reserved-word collision
  (plcc-ng 2.0.0 rejects a `var` field outright). The AST node class stays
  `VarExp`. This `SYMBOL`/`symbol` spelling is the standing convention for
  every language. Course material walking through V0 should refer to the
  `SYMBOL` token and the `symbol` field.
```
